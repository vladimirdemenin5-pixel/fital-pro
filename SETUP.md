# Fital Pro — подключение существующего сервиса

Проект использует Worker `red-waterfall-2af8`, базу D1 `fital-pro-db` и папку frontend `public/`.

## Уже реализовано в коде

- Выбор тарифа: Питание, PRO, Premium.
- Анкета с параметрами тела, целью, активностью, тренировками и пищевыми ограничениями.
- Генерация персонального меню через Workers AI на срок выбранного тарифа: 7 дней для «Питание», 14 дней для PRO и 30 дней для Premium.
- Показ примера плана до оплаты.
- Создание подписки после подтверждённого платежа Robokassa.
- Личный кабинет с полным меню, списком покупок, дневником прогресса и ИИ-консультантом.

## Cloudflare bindings

В существующем Worker должны быть доступны:
- AI binding с именем `AI`.
- D1 binding с именем `DB`, указывающий на `fital-pro-db`.
- Assets binding `ASSETS`, каталог `public`.

D1 database ID уже записан в `wrangler.jsonc`. Новую базу или Worker создавать не нужно.

## Секреты

В существующем production Worker уже используются следующие секреты:
- `ROBOKASSA_MERCHANT_LOGIN`
- `ROBOKASSA_PASSWORD1`
- `ROBOKASSA_PASSWORD2`

Для закрытых технических сценариев отдельно предусмотрены:
- `ROBOKASSA_TEST_PASSWORD1` и `ROBOKASSA_TEST_PASSWORD2` — тестовая пара паролей Robokassa.
- `ROBOKASSA_TEST_ACCESS_KEY` — ключ доступа к диагностике AI и тестовому checkout; не является паролем Robokassa.

Не публикуйте значения секретов в GitHub и не отправляйте их в чат.

Пароль №1 используется при создании платёжной ссылки. Пароль №2 — для проверки уведомления об оплате. Не отправляйте эти значения в чат и не записывайте в GitHub.

Для генерации планов используется внешний Groq API и существующий binding Cloudflare Workers AI `AI` как резерв:
- Основной внешний провайдер: Groq API, модель `openai/gpt-oss-20b`, если в существующем Cloudflare Worker настроен секрет `GROQ_API_KEY`.
- Резерв №1: Cloudflare Workers AI, модель `@cf/google/gemma-4-26b-a4b-it`.
- Резервы №2 и №3: Cloudflare Workers AI, модели `@cf/openai/gpt-oss-120b` и `@cf/openai/gpt-oss-20b`.
- Qwen 3.8 исключён из цепочки генерации планов. Для всех моделей сохраняется строгая серверная проверка JSON, меню, рецептов, граммовок, калорий и БЖУ.
- Groq использует отдельный серверный секрет `GROQ_API_KEY`; его наличие в Cloudflare нужно проверить отдельно. Не помещайте ключ в репозиторий или клиентский код.
- Cloudflare Workers AI и Groq имеют собственные лимиты и тарификацию; проверяйте актуальные условия в кабинетах провайдеров.

## Настройки Robokassa

В настройках магазина:
- ResultURL: `https://ВАШ-ДОМЕН/webhooks/robokassa`, отправка POST.
- Для самозанятого подключить в кабинете Robokassa сервис «Робочеки СМЗ» и подтвердить интеграцию с приложением «Мой налог»; платёжная ссылка Fital Pro передаёт номенклатуру услуги в `Receipt`.
- В тестовом платеже проверить, что после успешной оплаты сформирован чек НПД и он отправлен покупателю. Квитанция Robokassa сама по себе не заменяет чек НПД.
- SuccessURL: `https://ВАШ-ДОМЕН/`.
- FailURL: `https://ВАШ-ДОМЕН/?payment=fail`.
- Алгоритм подписи в кабинете и в настройках магазина: MD5.

При тестовом режиме используйте тестовые Пароль №1 и №2 в секретах Worker. Для боевого режима замените их на боевые пароли.

## D1

Используется существующая база `fital-pro-db` через binding `DB`. Старые таблицы Fital Pro сохраняются. Недостающая таблица заказов Robokassa `pending_orders` создаётся самим Worker через D1 binding при первом запросе оплаты; отдельный D1 Admin API token для обычной публикации не нужен.

Файл `migrations/0001_init.sql` оставлен для новой пустой базы или ручного администрирования. Команда `npm run db:migrate` нужна только при создании чистой базы и требует соответствующих прав D1.
